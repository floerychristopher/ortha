# ortha v1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Eine TUI-To-Do-App in C++20 (Linux + Windows) mit Startmenü, Today, All Tasks, Bearbeiten, Subtasks und wiederkehrenden Tasks, gespeichert in SQLite.

**Architecture:** `ortha_core` (statische Lib, keine UI) enthält Datum, Modell, SQLite-Wrapper, Repository, Service und Wiederholungslogik. `ortha_tui` (statische Lib) enthält die FTXUI-Views als Funktionen, die `ftxui::Component` liefern, und kommuniziert nur über Callbacks. `ortha` (Executable) ist nur `main.cpp`. Tests (Catch2) laufen gegen beide Libs; TUI-Views werden headless gerendert.

**Tech Stack:** C++20, CMake ≥ 3.25 + Ninja, FTXUI v6.1.9, SQLite 3.50.4 (Amalgamation), Catch2 v3.8.1, GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-10-07-ortha-design.md`

## Global Constraints

- C++20 (`CMAKE_CXX_STANDARD 20`, `CMAKE_CXX_STANDARD_REQUIRED ON`, keine Compiler-Extensions); muss mit GCC ≥ 14 und MSVC (VS 2022) bauen.
- Dependencies nur via FetchContent: FTXUI `v6.1.9`, Catch2 `v3.8.1`, SQLite-Amalgamation `https://www.sqlite.org/2025/sqlite-amalgamation-3500400.zip`.
- UI-Texte Englisch. Datumsanzeige und -eingabe `DD.MM.YYYY` (Spec: TT.MM.JJJJ); DB speichert ISO `YYYY-MM-DD`; Zeitstempel UTC `YYYY-MM-DDTHH:MM:SSZ`.
- IDs sind UUID v4 (lowercase), Löschen ist Soft-Delete (`deleted = 1`), jede Schreiboperation setzt `updated_at`.
- Bedienung nur Pfeiltasten, Enter, Esc (zurück), Tab. Keine Maus, keine CLI-Argumente.
- Namespace `ortha`; Includes relativ zu `src/` (`#include "core/date.hpp"`).
- Warnungen: GCC/Clang `-Wall -Wextra -Wpedantic`, MSVC `/W4 /utf-8` + `_CRT_SECURE_NO_WARNINGS`.
- Commits: Conventional-Style (`feat:`, `build:`, `test:`), jede Message endet mit `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- Arbeitsweise: vor jedem Task `git status` + betroffene Dateien neu lesen (der Nutzer schreibt evtl. selbst Code); nach jedem Task im Chat kurz die verwendeten C++-Konzepte erklären.
- Build/Test-Befehl überall: `cmake -S . -B build -G Ninja && cmake --build build && ctest --test-dir build --output-on-failure`

## Review Focus

1. **DB aus neuerer ortha-Version** (`user_version` > 1) → klare Fehlermeldung, Exit-Code 1, keine Datenänderung. Test in Task 5.
2. **Umlaute, Emoji, Anführungszeichen, Zeilenumbrüche** in Titel/Notizen → unverändert gespeichert und geladen. Test in Task 5.
3. **Ungültige oder knapp ungültige Daten** (`29.02.2027`, `31.04.2026`, `1.1.26`, `07.10.2026x`) → abgelehnt, nie stillschweigend korrigiert. Test in Task 2.
4. **Leerer oder nur aus Leerzeichen bestehender Titel** → Formular speichert nicht, zeigt Fehler. Test in Task 6.
5. **Wiederkehrenden Task doppelt abhaken** (abhaken → wieder öffnen → abhaken) → es entsteht nur EINE Folgeinstanz. Test in Task 13.

### Task 4: SQLite-RAII-Wrapper (`core/sqlite`)

**Files:** Create `src/core/sqlite.hpp`, `src/core/sqlite.cpp`, `tests/core/sqlite_test.cpp`; Modify CMakeLists.

**Interfaces:**
- Produces (Header deklariert nur `struct sqlite3; struct sqlite3_stmt;` vor, `sqlite3.h` bleibt in der .cpp):
  ```cpp
  namespace ortha {
  class SqliteError : public std::runtime_error { using std::runtime_error::runtime_error; };
  class Statement {
  public:
      Statement& bind(int index, std::string_view value);   // 1-basiert, SQLITE_TRANSIENT
      Statement& bind(int index, std::int64_t value);
      Statement& bind_null(int index);
      bool step();                                          // true = Zeile da, false = fertig; wirft bei Fehler
      std::string column_text(int col) const;               // 0-basiert; NULL -> ""
      std::int64_t column_int(int col) const;
      bool column_is_null(int col) const;
  private: /* unique_ptr<sqlite3_stmt, Finalizer> */
  };
  class Database {
  public:
      explicit Database(const std::string& utf8_path);      // ":memory:" erlaubt; setzt PRAGMA foreign_keys=ON
      void exec(const std::string& sql);                    // mehrere Statements erlaubt
      Statement prepare(const std::string& sql);
      void transaction(const std::function<void()>& fn);    // SAVEPOINT/RELEASE, bei Exception ROLLBACK TO + rethrow; verschachtelbar
      int user_version();
      void set_user_version(int version);
  private: /* unique_ptr<sqlite3, Closer> */
  };
  }
  ```
  Beide Klassen: move-only (folgt aus `unique_ptr`). Fehlermeldungen enthalten `sqlite3_errmsg`.

  ```cpp
  namespace ortha {
  enum class Priority { None = 0, Low = 1, Medium = 2, High = 3 };
  struct Subtask { std::string id; std::string title; bool done = false; };
  struct Task {
      std::string id, title, notes;
      std::optional<Date> due;
      Priority priority = Priority::None;
      bool done = false;
      std::optional<std::string> completed_at;
      std::vector<std::string> tags;          // normalisiert, sortiert
      std::vector<Subtask> subtasks;          // Reihenfolge = position
      std::string created_at, updated_at;
  };
  std::vector<std::string> parse_tags(std::string_view input);   // trim, lowercase (ASCII), leer raus, sortiert, unique
  std::string join_tags(const std::vector<std::string>& tags);   // "home, work"

  class TaskRepository {
  public:
      explicit TaskRepository(Database& db);   // migriert; wirft SqliteError wenn user_version > 1
      void insert(Task& task);                  // setzt id (wenn leer), Subtask-ids, created_at, updated_at
      void update(Task& task);                  // setzt updated_at; ersetzt Tags; Subtasks: alte soft-deleten, aktuelle upserten
      void remove(const std::string& id);       // Soft-Delete
      std::optional<Task> find(const std::string& id);
      std::vector<Task> all(bool include_done);
      std::vector<Task> due_by(Date day, bool include_done);   // due_date <= day, ohne Datum ausgeschlossen
      Database& database();                     // für TaskService-Transaktionen
  };
  }
  ```

Sortierung aller Listen in SQL: `ORDER BY done, due_date IS NULL, due_date, priority DESC, created_at`. insert/update laufen jeweils in `db.transaction`.

### Task 12: Wiederholungsregeln (`core/recurrence`)

**Interfaces:**

- Produces:
  ```cpp
  namespace ortha {
  enum class Frequency { Daily, Weekly, Monthly, Yearly };
  enum class Anchor { Due, Completion };
  struct RecurrenceRule {
      Frequency freq = Frequency::Daily;
      int interval = 1;                              // >= 1
      std::vector<std::chrono::weekday> weekdays;   // nur Weekly; sortiert Mo..So; leer = alle `interval` Wochen
      Anchor anchor = Anchor::Due;
      bool operator==(const RecurrenceRule&) const = default;
  };
  std::string serialize(const RecurrenceRule& rule);                    // "FREQ=WEEKLY;INTERVAL=2;BYDAY=MO,WE,FR;FROM=DUE" (BYDAY nur wenn nicht leer)
  std::optional<RecurrenceRule> parse_recurrence(std::string_view text); // FREQ Pflicht; INTERVAL Default 1, muss >= 1; FROM Default DUE (DUE|COMPLETION); BYDAY nur bei WEEKLY; sonst nullopt
  Date next_due(const RecurrenceRule& rule, Date base);
  }
  ```
  `next_due`: Daily `+interval` Tage; Monthly/Yearly `+interval` Monate/Jahre, ungültiges Datum → letzter Tag des Monats; Weekly ohne Tage `+7·interval` Tage. Weekly mit Tagen:
  ```
  b = ISO-Wochentag(base) (Mo=1..So=7)
  gibt es einen gewählten Tag d > b  → base + (d − b) Tage
  sonst → Montag(base-Woche) + interval Wochen + (erster gewählter Tag − 1) Tage
  ```

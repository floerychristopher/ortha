# Goals (Tagesziele) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Habit-Tracker-Ziele mit Wochentagen, Status pro Tag (offen/✓/✗), Streak, Verlauf mit Nachtragen; sichtbar in Today und im neuen Menüpunkt „Goals“.

**Architecture:** Neues Schema-Modul migriert die DB auf v2 (`goals`, `goal_entries`). `core/goal` enthält reine Funktionen (Planung, Streak, 7-Tage-Leiste), `core/goal_repository` die Persistenz und `summary()`. In der TUI bekommt `home_view` einen Goals-Abschnitt (als Header der bestehenden `TaskView`), dazu kommen `goals_view`, `goal_history_view`, `goal_form`. `App` verdrahtet alles.

**Tech Stack:** wie bisher – C++20, FTXUI v6.1.9, SQLite, Catch2.

**Spec:** `docs/superpowers/specs/2026-10-07-goals-design.md`

## Global Constraints

- Alle Global Constraints aus `docs/superpowers/plans/2026-10-07-ortha-v1.md` gelten (C++20, Namespace `ortha`, Warnungen, UI-Texte Englisch, nur Pfeiltasten/Enter/Esc/Tab).
- **Commits nur auf ausdrückliche Anweisung des Nutzers**, ohne `Co-Authored-By`. Die Commit-Schritte unten sind Vorschläge.
- Status-Zyklus überall: `open` → `done` → `missed` → `open`.
- Symbole exakt: `[ ]`, `[✓]`, `[✗]`; Leiste `✓` `✗` `○` `·`; Streak `🔥 N` (nur bei N > 0).
- Wochentage immer Montag-zuerst indiziert (0 = Mo … 6 = So); DB-Bitmaske Bit 0 = Mo.
- Vor jedem Task `git status` + betroffene Dateien neu lesen; nach jedem Task C++-Konzepte kurz im Chat erklären.
- Build/Test: `cmake --build build && ctest --test-dir build --output-on-failure`

## Review Focus

1. **Bestehende v1-Datenbank mit Tasks** → wird auf v2 migriert, alle Tasks bleiben. Test in Task 1.
2. **Tage vor dem Anlagedatum** → zählen weder im Streak noch im Verlauf noch in der Leiste. Tests in Task 2.
3. **Wochentage nachträglich geändert** → Einträge an jetzt nicht mehr geplanten Tagen werden im Streak übersprungen (weder gezählt noch Bruch). Test in Task 2.
4. **Status mehrfach gewechselt / zurück auf offen** → genau eine Zeile pro (Ziel, Tag), Status korrekt. Test in Task 3.
5. **Gelöschtes Ziel** → verschwindet aus Today und Goals, Einträge bleiben in der DB. Test in Task 3.

### Task 2: Goal-Modell und reine Funktionen

**Files:** Create `src/core/goal.hpp`, `src/core/goal.cpp`, `tests/core/goal_test.cpp`; Modify CMakeLists.

**Interfaces:**
- Consumes: `Date` (date.hpp).
- Produces:
  ```cpp
  namespace ortha {
  enum class GoalStatus { Open, Done, Missed };
  using Weekdays = std::array<bool, 7>;   // Monday..Sunday
  struct Goal {
      std::string id, title;
      Weekdays weekdays{true, true, true, true, true, true, true};
      Date start;                          // local date the goal was created
      std::string created_at, updated_at;
  };
  using StatusLookup = std::function<GoalStatus(Date)>;

  int weekday_index(Date day);                        // 0 = Monday .. 6 = Sunday
  bool is_scheduled(const Goal& goal, Date day);      // weekday chosen and day >= start
  GoalStatus next_status(GoalStatus status);          // Open -> Done -> Missed -> Open
  int streak(const Goal& goal, Date today, const StatusLookup& status_of);
  // Last 7 days, oldest first; nullopt = not scheduled that day.
  std::array<std::optional<GoalStatus>, 7> last_week(const Goal& goal, Date today, const StatusLookup& status_of);
  std::vector<Date> scheduled_days(const Goal& goal, Date today);   // start..today, newest first
  std::string weekdays_label(const Weekdays& days);   // "daily" or e.g. "Mo We Fr"
  }
  ```
  `streak`: heute geplant und `Missed` → 0; heute `Done` → zählt 1; heute `Open`/nicht geplant → übersprungen. Dann rückwärts ab gestern bis `start`: nicht geplante Tage überspringen, `Done` zählt, alles andere bricht ab.

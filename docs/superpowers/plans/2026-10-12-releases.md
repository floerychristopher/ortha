# Releases und Scoop Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ein Tag `vX.Y.Z` erzeugt automatisch ein GitHub-Release mit `ortha.exe` (zip) und Linux-Binary und aktualisiert das Scoop-Manifest im Repo; `ortha --version` zeigt die Version.

**Architecture:** Version aus `project(VERSION)` per `configure_file` als `ortha::kVersion`. Zwei kleine, lokal testbare Skripte (`scripts/check-tag-version.sh`, `scripts/update-scoop-manifest.py`) tragen die Logik, `.github/workflows/release.yml` ruft sie nur auf. `bucket/ortha.json` macht das Repo zum Scoop-Bucket.

**Tech Stack:** CMake, GitHub Actions, Bash, Python 3 (Standardbibliothek), Scoop.

**Spec:** `docs/superpowers/specs/2026-10-12-releases-design.md`

## Global Constraints

- Alle bisherigen Global Constraints gelten (C++20, keine Warnungen, Commits nur auf Anweisung, ohne `Co-Authored-By`).
- Repo-URL exakt `https://github.com/floerychristopher/ortha`; Archivnamen exakt `ortha-<version>-windows-x64.zip` / `ortha-<version>-linux-x64.tar.gz`; Prüfsummendatei `SHA256SUMS.txt`; Manifest-Commit `chore(scoop): ortha <version>`.
- Skripte ohne externe Abhängigkeiten (Bash + Python-Standardbibliothek), damit sie auf den GitHub-Runnern ohne Installation laufen.
- Skript-Tests nur außerhalb von Windows registrieren (`if(NOT WIN32)`), die Windows-CI baut und testet nur C++.
- Build/Test: `cmake --build build && ctest --test-dir build --output-on-failure`

## Review Focus

1. **Tag passt nicht zur Version** (z.B. `v0.2.1` bei `0.2.0`, Tag ohne `v`) → Release bricht vor dem Bauen mit klarer Meldung ab. Test in Task 2.
2. **Manifest-Update ändert nur `version`, `url`, `hash`** und lässt alle anderen Felder, ihre Reihenfolge und gültiges JSON intakt; zweimal hintereinander ausgeführt bleibt das Ergebnis gleich. Test in Task 2.
3. **`ortha --version` öffnet keine Datenbank und kein UI** (läuft auch ohne Terminal, z.B. in der CI). Test in Task 1.
4. **Der Manifest-Commit der CI** kollidiert nicht mit einem inzwischen neueren `main` (Push schlägt fehl → Job rebased einmal und versucht erneut). Geprüft im Workflow-Review (Task 3).
5. **Unbekannte Argumente** → Meldung auf stderr, Exit 2, kein UI. Test in Task 1.

### Task 2: Release-Skripte und Scoop-Manifest

**Files:** Create `scripts/check-tag-version.sh`, `scripts/update-scoop-manifest.py`, `bucket/ortha.json`, `tests/scripts/test_release_scripts.sh`; Modify `tests/CMakeLists.txt`.

**Interfaces:**
- `scripts/check-tag-version.sh <tag> [<cmakelists>]` → Exit 0 wenn `<tag>` == `v` + Version aus `project(... VERSION x.y.z ...)`, sonst stderr `Tag <tag> does not match the version <x.y.z> in CMakeLists.txt` und Exit 1; gibt bei Erfolg die Version auf stdout aus.
- `scripts/update-scoop-manifest.py <manifest> <version> <sha256>` → setzt `version`, `url` (aus `autoupdate.url` mit `$version` ersetzt), `hash`; schreibt mit 2 Leerzeichen Einrückung, `ensure_ascii=False`, abschließendem Zeilenumbruch; Feldreihenfolge bleibt; Fehler bei ungültigem SHA-256 (nicht 64 Hex-Zeichen) → Exit 1.
- `bucket/ortha.json` laut Spec, `version` `0.2.0`, `hash` `0000…` (64 Nullen) als Platzhalter.

- [ ] **Step 1: Failing test** `tests/scripts/test_release_scripts.sh` (Bash, `set -euo pipefail`, Temp-Verzeichnis), registriert als CTest `release_scripts` (`if(NOT WIN32)`):
  - `check-tag-version.sh v0.2.0` → Exit 0, Ausgabe `0.2.0`; `v0.2.1`, `0.2.0`, `v0.2` → Exit 1 mit Meldung (Review Focus 1).
  - `update-scoop-manifest.py` auf einer Kopie: danach `version`=`0.3.0`, `url` endet auf `/v0.3.0/ortha-0.3.0-windows-x64.zip`, `hash` gesetzt; `description`, `bin`, `checkver`, `autoupdate` unverändert; Feldreihenfolge gleich; zweiter Lauf → Datei byte-gleich (Review Focus 2); ungültiger Hash → Exit 1, Datei unverändert.
  - `bucket/ortha.json` ist gültiges JSON mit allen Pflichtfeldern.

### Task 3: Release-Workflow

**Files:** Create `.github/workflows/release.yml`.

Jobs laut Spec: `check-version` (ubuntu, ruft `check-tag-version.sh "$GITHUB_REF_NAME"`, gibt `version` als Output) → `build` (Matrix wie `ci.yml`, `-DCMAKE_BUILD_TYPE=Release`, `ctest`, packen, `actions/upload-artifact`) → `release` (`actions/download-artifact`, `sha256sum` → `SHA256SUMS.txt`, Release per `gh release create "$GITHUB_REF_NAME" --generate-notes <dateien>`) → `scoop` (checkout `main`, Hash aus `SHA256SUMS.txt`, `update-scoop-manifest.py`, Commit als `github-actions[bot]`, `git push`; bei abgelehntem Push einmal `git pull --rebase` und erneut). `permissions: contents: write` nur wo nötig.
